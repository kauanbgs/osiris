2. CORREÇÃO NA PÁGINA NAVEGADOR (Navegador.jsx)
--------------------------------------------------------------------------------
PROBLEMAS IDENTIFICADOS:
a) Ao clicar no botão "+", o navegador ficava completamente preto e não abria a nova guia.
   - Causa 1: A função `addTab` era assíncrona e executava `await sheets.createBrowserSession("about:blank")`
     antes de atualizar o estado do React (`setTabs`/`setActiveTabId`). Caso a API demorasse para responder
     ou estivesse offline, a interface congelava sem adicionar a guia.
   - Causa 2: Cada guia sem URL (`url: ""`) recebia um elemento `<webview src="about:blank">` com a classe `hidden`
     (`display: none !important`). No Electron / Chromium, aplicar `display: none` em `<webview>` desanexa
     a superfície nativa de renderização GPU ou causa crash de composição, tornando o container do Chromium
     completamente preto.
   - Causa 3: Havia referência incorreta `webviewRef` (singular) vs `webviewRefs` (plural/mapa por aba), impedindo
     o registro das instâncias no mapa de referências.

CORREÇÕES APLICADAS:
- `addTab` síncrono e instantâneo: Cria imediatamente a aba no React (`setTabs` e `setActiveTabId`) sem aguardar
  requisições de rede. A criação de sessão da API ocorre de forma desacoplada em segundo plano.
- Montagem condicional do `<webview>` nativo: Somente guias que possuem uma URL real (`tabs.filter(t => t.url)`)
  renderizam uma instância de `<webview>`. Guias recém-criadas ou na tela inicial ("Nova Guia") exibem diretamente
  a UI nativa do Osíris (atalhos de Acesso Rápido, barra de busca) com `z-10 bg-surface-0`, sem instanciar
  processos desnecessários de `<webview>` em branco.
- Ocultamento seguro sem `display: none`: Para guias com URL que não são a aba ativa no momento, a alternância
  é controlada via `visibility: isCurrentActive ? 'visible' : 'hidden'` com `pointerEvents: isCurrentActive ? 'auto' : 'none'`,
  preservando o contexto gráfico e a textura GPU sem telas pretas.
- Navegação unificada em `navigateTo`: Quando o usuário digita na barra ou clica em um atalho de acesso rápido:
  * Se a guia já possuía um `<webview>`, navega via `webview.loadURL(formatted)`.
  * Se a guia estava na tela inicial (`url: ""`), o React monta a instância com `src={formatted}`, iniciando
    o carregamento nativo e anexando os ouvintes de evento via callback de referência.
- Limpeza no `closeTab`: Ao fechar uma guia, os ouvintes de eventos e as referências no mapa `webviewRefs`
  são removidos com segurança para evitar vazamento de memória.
- Tratamento visual de erro de carregamento: Caso ocorra falha de rede ou DNS (`did-fail-load`), uma tela de erro
  amigável é exibida sobre a guia com opções de "Tentar novamente" (`reload()`) e "Abrir no navegador".


3. CORREÇÃO NA PÁGINA TERMINAL (Terminal.jsx e ElectronTerminalPanel.jsx)
--------------------------------------------------------------------------------
PROBLEMAS IDENTIFICADOS:
a) Erro ao usar e alternar múltiplas abas de terminal:
   - Causa: `Terminal.jsx` utilizava `key={activeTabId}` no painel ativo (`<ElectronTerminalPanel key={activeTabId} />`).
     Ao clicar no "+" ou alternar entre abas ("Terminal 1", "Terminal 2"), o React desmontava o painel da aba anterior.
   - A função de limpeza do unmount em `ElectronTerminalPanel.jsx` disparava `window.electronAPI.terminalClose(terminalId)`,
     que executava `terminal.kill()` no processo PowerShell em background do Electron.
   - Ao retornar à aba anterior, o processo já havia sido encerrado abruptamente no sistema operacional,
     causando mensagens de erro ("Terminal encerrado") e perda total do histórico digitado.

CORREÇÕES APLICADAS:
- Preservação de abas em segundo plano: `Terminal.jsx` agora renderiza as abas mantendo suas instâncias vivas,
  alternando a visibilidade via CSS (`${isActive ? "block" : "hidden"}`).
- Encerramento sob demanda: O comando `terminalClose` agora só é acionado quando o usuário clica explicitamente
  no botão "X" de fechar a aba (`removeTab`).
- Reajuste automático ao focar: Adicionada a propriedade `isActive` ao `ElectronTerminalPanel`. Quando a aba volta
  a ficar ativa, um efeito executa `fitAddon.fit()` e `xterm.focus()` para readequar as dimensões do terminal (linhas/colunas)
  e devolver o foco ao cursor.
