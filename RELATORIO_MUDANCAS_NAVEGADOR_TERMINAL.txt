1. CAUSA RAIZ DA TELA PRETA AO ACESSAR SITES (GOOGLE, GITHUB, PESQUISAS)
--------------------------------------------------------------------------------
Identificamos a causa definitiva do erro de tela preta ao navegar ou pesquisar:

A) Disparo indevido de `did-fail-load` para sub-recursos (imagens, trackers, ads):
   - No Electron, o evento `did-fail-load` do `<webview>` é disparado para QUALQUER
     recurso que falhe ou seja cancelado, incluindo requisições de analytics,
     pre-fetches, anúncios e imagens secundárias.
   - O handler anterior não verificava `e.isMainFrame`. Assim que o Google ou GitHub
     iniciava o carregamento e cancelava uma requisição secundária (como fontes ou
     rastreadores bloqueados), o estado `loadError` era imediatamente ativado.
   - Isso renderizava uma tela de sobreposição de erro estilizada com `bg-surface-0`
     (cor `#101012`, praticamente preta) com `absolute inset-0 z-20`, cobrindo
     completamente a página que estava tentando carregar!

B) Loop de re-navegação e cancelamento no React 19 (`src={tab.url}`):
   - No React 19, propriedades em Custom Elements (`<webview>`) chamam diretamente
     o setter de atributo do elemento nativo.
   - Ao navegar para `google.com`, o Google realiza múltiplos redirecionamentos HTTP
     internos (ex: para `https://www.google.com/?gws_rd=ssl`).
   - O evento `did-navigate` capturava a nova URL redirecionada e atualizava o estado
     `tab.url` no React. Ao re-renderizar com o novo `src`, o React forçava o Chromium
     a abortar o carregamento em andamento e iniciar uma nova navegação do zero.
   - Esse ciclo de abortos sucessivos (`ERR_ABORTED -3`) travava o renderizador
     do Chromium, deixando a tela branca ou preta.

C) Altura colapsada do container flex (`h-full` vs `flex-1 min-h-0`):
   - O elemento pai do `<webview>` possuía `className="relative h-full w-full"`.
     Como seus filhos eram `position: absolute`, o container em um layout flex-col
     colapsava para 0px de altura em determinados fluxos, expondo o fundo `#101012`
     (preto) da página principal.

D) Vazamento de chamada da API Playwright:
   - Em `navigateTo`, ao tentar navegar em uma guia recém-aberta onde o webview ainda
     não tinha sido indexado no mapa, a função não retornava no modo Electron,
     fazendo fallback indevido para o backend Playwright.


2. CORREÇÕES IMPLEMENTADAS
--------------------------------------------------------------------------------
1. Filtragem estrita em `handleFailLoad`:
   - Adicionada a validação `if (e.isMainFrame === false) return;`.
   - Adicionado descarte de erros de cancelamento `if (e.errorCode === -3 || e.errorCode === 0) return;`.
   - Agora, falhas de scripts de terceiros ou cancelamentos normais de stream HTTP/2
     nunca mais disparam a sobreposição de erro, permitindo que Google e GitHub
     carreguem normalmente.

2. Navegação desacoplada e imperativa via `loadURL()`:
   - O `<webview>` agora é montado sem a propriedade reativa `src` no JSX.
   - O carregamento da página é feito exclusivamente via `loadURL()` no evento
     `dom-ready` e na função `navigateTo()`.
   - As atualizações de `did-navigate` (para barra de endereços e histórico) não
     interferem mais no ciclo de renderização do Chromium, eliminando 100% dos loops
     de redirecionamento.

3. Correção do Container e Layout:
   - O container agora utiliza `className="relative flex-1 min-h-0 w-full h-full bg-white"`.
   - O `<webview>` possui `display: "flex", width: "100%", height: "100%"`.
   - Isso garante que a área de exibição ocupe 100% da viewport e que o fundo base
     seja branco, como em um navegador nativo.

4. Isolamento definitivo no Electron:
   - `navigateTo()` no Electron agora sempre retorna antes de qualquer chamada
     Playwright (`return;`), garantindo que apenas o Chromium local gerencie a renderização.

5. Preservação de Sessões no Terminal:
   - Múltiplas abas de terminal agora permanecem vivas no DOM em segundo plano,
     evitando que a alternância de abas mate o processo PowerShell (`pty.kill()`).
   - `terminalClose` só é chamado quando a aba é fechada explicitamente no "X".
